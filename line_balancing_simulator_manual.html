1. สินค้าและ Product Packaging Master

  1. เลือกสินค้าและตรวจสูตรบรรจุตรวจน้ำหนักต่อถุง (g), ถุงต่อกล่อง และกล่องต่อพาเลท ค่าที่อ่านจากชื่อสินค้าหรือข้อมูลตั้งต้นไม่ใช่ specification ที่อนุมัติแล้ว
  2. ระบุแหล่งข้อมูลเลือก assumption/catalog สำหรับค่ารอการยืนยัน หรือ standard/trial เมื่อมีหลักฐานจริง ห้ามเปลี่ยนประเภทเพียงเพื่อให้สถานะผ่าน
  3. ตั้งเป้าหมายเครื่องTarget หน่วย kg/hr ตั้งแต่ 100, Safety Buffer 0–50%, Baseline กำลังคนเป็นจำนวนเต็มตั้งแต่ 1 และน้ำหนักต้องมากกว่า 0

kg/ถุง = g/ถุง ÷ 1,000; kg/กล่อง = kg/ถุง × ถุง/กล่อง; kg/พาเลท = kg/กล่อง × กล่อง/พาเลท

การแสดง kg/min หรือกล่อง/นาทีเป็นการเปลี่ยนหน่วยแสดงผล ฐานคำนวณกำลังผลิตยังเป็น kg/hr ส่วน Feed แบบถาดต้องระบุน้ำหนักเฉลี่ยต่อถาด

2. คำแนะนำกำลังคน

เปิดรายละเอียดสถานี ตรวจ Productivity ต่อทีม, Team size, จำนวนคน, แหล่งข้อมูล และ Use in capacity สถานีที่ปิดการใช้กำลังผลิตไม่ร่วมคำนวณคอขวด แต่กำลังคนยังอยู่ในยอดรวม

โหมด/คำสั่งพฤติกรรม
ตาม Target (Lean)เสนอจำนวนทีมให้ถึง Target
รวม Safety Buffer (Safe)เสนอจำนวนทีมให้ถึง Target × (1 + Buffer/100)
ใช้กำลังคนที่แนะนำถามยืนยันก่อนเปลี่ยนสถานีที่ไม่ Lock ถ้าเกินช่วง slider จะขยาย maxPeople เช่น 4 คน/ช่วงสูงสุด 8 → 17 คน/ช่วงสูงสุด 17 ไม่ใช่เพดานกำลังคนหน้างาน
Lock / ไม่ใช้ใน capacityไม่เปลี่ยนกำลังคนตามคำแนะนำ

ทีมครบ = floor(คน ÷ Team size); Capacity = ทีมครบ × Productivity ต่อทีม คนที่เหลือไม่ครบทีมไม่เพิ่ม Capacity และ Productivity เป็นศูนย์ไม่สามารถเพิ่มกำลังผลิตด้วยการเพิ่มคนได้

ผลจำลองไม่ใช่การอนุมัติลดคนต้องทบทวนข้อจำกัดหน้างาน ความปลอดภัย คุณภาพ และผล Trial ก่อนนำไปใช้จริง สถานะ “พร้อมทบทวน” ไม่แทนการอนุมัติของผู้รับผิดชอบ

3. Scenario พาเลท

เลือกสินค้า ตรวจความจุพาเลท น้ำหนักต่อกล่อง ความเร็ว FG เวลา Scenario และเวลาสูญเสียในการเปลี่ยนพาเลท เลือกฐานความเร็วจากเป้าหมายเครื่องหรือฐาน Item ให้ตรงเจตนาทดลอง

กล่องเต็มปัดลงจากจำนวนตามทฤษฎี เศษที่ยังไม่เต็มกล่องเป็น WIP; ปริมาณไม่เกินความจุพาเลท กำลังผลิตสุทธิ = กำลังผลิตตามฐาน × เวลาที่ใช้ ÷ (เวลาที่ใช้ + เวลาสูญเสีย)

เปิด Auto link เพื่ออัปเดตสถานี “กำลังผลิตพาเลท” ใน Process Flow หรือหยุด Auto link แล้วกดเชื่อมเอง สถานีนี้เป็นกำลังผลิตภายนอกที่ใช้กำลังคน 0 ในแบบจำลอง ไม่ใช่จำนวนพนักงานพาเลทจริง

เวลาและอุณหภูมิเวลาสัมผัสที่ลดลงเป็นผลคำนวณ ต้องวัดอุณหภูมิจริงและยืนยันคุณภาพใน Trial ไม่สามารถใช้การลดเวลาเป็นหลักฐานว่าคุณภาพผ่านแล้ว

4. Evidence และ Trial readiness

  • สถานี Actual/Trial ต้องมีแหล่งข้อมูล วันที่ จำนวนตัวอย่างจำนวนเต็มมากกว่า 0 และผู้รับผิดชอบ
  • Assumption/Target ใช้เพื่อวางแผน ไม่ใช่ผลวัดจริง
  • บันทึกผล Trial เป็น passed/failed ตามจริง พร้อมวันที่ ผู้อนุมัติ และ checklist WIP, Delays, Breaks, Ergonomics
  • Capacity ต่ำกว่า Target หรือ Safety Buffer จะแจ้งเตือน แม้กรอก Trial ครบแล้ว

Scenario A/B เก็บ evidence และ Trial ของตัวเอง การส่ง log จะประเมินสถานะจาก snapshot นั้น ไม่ใช้สถานะของ workspace ปัจจุบันแทน

5. บันทึก กู้คืน และแลกเปลี่ยน JSON

คำสั่งการใช้งาน
บันทึกปัจจุบันเป็น A / Bเก็บก่อนปรับและข้อเสนอ/ผลทดลอง การบันทึกทับถามยืนยัน
โหลด A / Bถามยืนยันก่อนแทนค่าปัจจุบัน รวม evidence และ Trial
ย้อนกลับ (Undo)ย้อนรายการที่ระบบเก็บไว้ได้สูงสุด 20 รายการใน session ไม่ใช่ประวัติถาวรข้ามเครื่อง
ส่งออก JSONสำรอง workspace, A/B, evidence และข้อมูลพาเลท ต้องผ่าน validator ไม่มี token ในไฟล์ส่งออก
นำเข้า JSONไฟล์ไม่เกิน 500,000 bytes ตรวจ schema/ID ไม่ซ้ำ/โครงสร้างก่อนถามยืนยัน ไฟล์เสียหรือรุ่นใหม่กว่าจะถูกปฏิเสธ

localStorage และการใช้สองรุ่น

รุ่นหลักใช้ schema 4; Line Balancing เดิมเป็น legacy schema 3 ใช้ key หลักเดิมร่วมกัน เมื่อพบข้อมูลรุ่นใหม่กว่า รุ่นเก่าจะไม่บันทึกทับ และตรวจเวอร์ชันซ้ำก่อนบันทึกทุกครั้ง

ก่อนอัปเกรด schema ระบบสำรองข้อความ JSON เดิมไว้ใน key ย่อยที่ลงท้ายด้วย backup.schema และเวลา หากสำรองไม่ได้จะไม่เขียนทับข้อมูลเดิม key หลักไม่ถูกย้าย

ควรส่งออกไฟล์สำรองข้อมูลผูกกับ browser/profile/origin ไม่ได้ส่งไปอีกเครื่องโดยอัตโนมัติ file:// และ GitHub Pages อาจใช้พื้นที่เก็บข้อมูลคนละชุด Private mode, quota, การล้าง browser หรือเปลี่ยน URL อาจทำให้กู้คืนไม่ได้ หากพบ autosave unavailable ให้เก็บ JSON ก่อนตรวจพื้นที่จัดเก็บ อย่าลบข้อมูลเดิมเพื่อแก้ปัญหาโดยไม่มีสำรอง

6. Google Sync

กรอก URL และ token ของระบบที่ผู้รับผิดชอบจัดให้ ไม่ได้ตั้งหรือเปลี่ยน endpoint ให้โดยคู่มือนี้ token เก็บใน browser ไม่ควรใช้บนเครื่องสาธารณะ และต้องไม่เผยแพร่พร้อม source หรือภาพหน้าจอ

สถานะความหมาย
ตั้งค่าแล้วมี URL/token เท่านั้น ยังไม่ยืนยันสิทธิ์หรือการบันทึก
กำลังส่งคำขอยังไม่เสร็จ มีเวลารอสูงสุด 15 วินาที
ส่งแล้ว ยังไม่ยืนยันการส่งแบบ no-cors ได้ opaque response อ่านผลการบันทึกไม่ได้ ต้องตรวจ Event_Log ที่ปลายทาง ไม่แสดงว่า Connected/Synced
ส่งไม่สำเร็จnetwork error/หมดเวลา/คำขอถูกปฏิเสธ ผลบันทึกปลายทางอาจยังไม่ทราบ ตรวจ log ก่อนส่งซ้ำ
ยืนยันแล้วต้องได้ response ที่อ่านได้และ acknowledgment ตรง requestId พร้อม accepted=true และ written=true เท่านั้น ขณะนี้ transport no-cors ยังไม่ให้การยืนยันแบบ end-to-end

เมื่อเปิดการตั้งค่า Sync การบันทึก workspace จะจัดคิวส่ง log อัตโนมัติด้วย การเพิ่ม acknowledgment/CORS และป้องกันรายการซ้ำที่ backend เป็นงานแยก ยังไม่ได้ deploy หรือทดสอบส่งข้อมูลจริง
